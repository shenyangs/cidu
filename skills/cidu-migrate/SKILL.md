# 词渡迁移

词渡负责确定性的解析、引擎验证、备份和安装。你负责理解需求、解释检查结果、处理用户选择，不要自行改写输入法数据库或猜测未知格式。

## 找到 CLI

优先使用用户提供的词渡应用路径。CLI 位于 `词渡.app/Contents/MacOS/cidu-cli`，与 `EngineProbe` 同目录；不要只复制单个可执行文件。若本 Skill 位于应用 Resources 内，CLI 相对路径为 `../../MacOS/cidu-cli`。若 Skill 被单独安装而没有应用路径，查找 `/Applications/词渡.app` 和 `~/Applications/词渡.app`，找不到时向用户询问应用位置。命令中的路径必须作为独立、正确引用的参数传递。

以下 `cidu-cli` 均指上一步找到的完整可执行文件路径；先执行该路径加 `help`，以实际版本输出为准。仅适用于 macOS；当前不提供 MCP 服务。

## 工作流

- `cidu-cli status` 检查百度自动读取到豆包的可用性。用户有导出文件时用 `cidu-cli status --file PATH`，文件分支不要求来源输入法安装或自动导出权限。
- `cidu-cli plan [--file PATH]` 在本机私有目录创建备份与候选词库，执行合并及原生引擎验证，返回计划 ID、新增数、已存在数和 `unmigrated` 数。0.8 会保留完整来源、未迁移档案与原因清单。不会安装词库；自动读取分支会操作百度官方设置窗口导出，事先说明这一动作。
- 用用户能理解的语言报告计划，包括来源、目标、计数和是否还需处理问题。用户只要求检查或查看计划时，到此停止。生成计划不代表迁移完成。
- 在用户已授权该次迁移的范围内执行 `cidu-cli apply ID --confirm`。`--confirm` 是有意执行写入的标记，不能替代用户授权；已有明确迁移授权时不重复索取。计划有效期 24 小时，目标内容改变、版本或账号变化都会拒绝。失败后依据检查结果处理，过期或变化需重新生成并重新评估；不循环盲试，不跳过检查。
- 当计划 `partialConfirmationRequired:true` 时，说明未迁移数量及档案已保留。仅在用户明确接受这次部分迁移时使用 `apply ID --confirm --allow-partial`；一般迁移授权不等于接受丢下部分词条。已有明确的部分迁移授权时不重复询问。无可新增词条时保留档案，不尝试安装。
- `cidu-cli history` 列出统计和记录。仅 `installed` 表示已经安装，`prepared` 未安装，`unchanged` 无新增，`restored` 已恢复；`unmigrated` 非零的 installed 仅表示部分完成，不能说全部成功。`interrupted` 表示中断后目标内容无法与快照匹配，停止写入并解释原因。旧记录的 `existing:null` 表示未知，不能解释为零。
- 用户要求撤销时选择对应已安装记录，执行 `cidu-cli restore ID --confirm`。若迁移后词库又学习了新内容，恢复会拒绝；不要强制覆盖或替用户删除新词。

## 输出与权限

stdout 是一条 JSON；退出码 0 为成功、2 为环境未就绪、1 为参数或操作错误。status 的 `ok:true` 只表示检查完成，必须看 `ready`。只向用户报告实际返回的结果。

CLI 默认不输出词语、源文件内容或原生引擎日志。不要把完整词库、备份或原始日志送给远程模型；讨论计数、检查项和错误即可。私有数据留在本机 Application Support/Cidu/Transactions。计划 ID 不是密码或授权凭证。

CLI 与桌面可能具有不同的系统权限归属；不要承诺 Agent 有更多权限。权限失败时解释 status 的处理建议，引导用户在系统设置为实际请求权限的应用授权，或改用已导出文件。不要修改 TCC 数据库、自动开启权限或借别的进程绕过权限。
